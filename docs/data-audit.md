## 2. 마을 판정 (`src/api/judge.ts`)

서버 판정 규칙이 문서에 없어 서버 결과에 맞춰 알아낸 규칙이다. 화면은 서버 결과가 오면 `compare()`로 대조하고, 다르면 서버 결과를 쓴다(`src/hooks.ts` `useShownJudge`).

### 2-1. 대중교통 판정 `judgeLocal` (서버 판정과 같은 규칙)

```
busOk = 정류장 있음 AND 정류장까지 걷는 분 ≤ stopWalkMinutes
정밀 지역이면 추가로: AND 하루 운행 ≥ dailyRuns AND 읍내행 첫차 존재 AND 첫차 < 12:00(720분)

서비스 '버스 이용'  : busOk → 0(갈 수 있음) / 아니면 1(버스 없어 못 감)
서비스 '병원 가는 길':
  마을 안에 병의원 있음                       → 0
  가장 가까운 병의원 자가용 분 > carMinutes   → 2(너무 멀어 못 감)  (자료 없으면 ∞ → 2)
  그 외                                       → busOk ? 0 : 1
```

| 값 | 기준·근거 |
|---|---|
| 첫차 기준 720분 | 서버 결과에서 688분 통과, 732분 탈락 → 12:00로 추정. 정확히 720분은 탈락(서버도 `<`) |
| 간이 판정 지역 | 하루 운행·첫차 자료 없음 → 정류장 거리만 봄 |
| 합계 `summarize` | 공백 = 상태 1·2 인구 합, 비율 = 공백/전체(소수 4자리 반올림) |

### 2-2. 시설 필터 판정 (서버 시험안, 화면 전용)

- 필터: 모든 병의원 · 병원·종합병원 · 동네 의원 · 보건소·진료소 · 응급의료센터
- 병원급·의원·보건기관: `nearest.med` 대신 `nearest.byKind[필터]` 분, "마을 안 시설"도 그 종류만 봄
- 응급의료센터: `nearest.er.center.minutes ≤ carMinutes`면 0, 아니면 2. 버스·마을 안 병의원은 보지 않음
- 서버 판정 대조는 '모든 병의원'일 때만 함(서버는 필터를 모름)

시설 종별 정규식 `KIND_RE` — **실데이터와 대조 결과 문제 없음**

| 필터 | 정규식 | 실제 종별(72개 지역) | 매칭 |
|---|---|---|---|
| 병원급 | `/병원\|종합/` | 병원 96, 종합병원 18, 상급종합 1 | ✓ (보건의료원은 걸리지 않음) |
| 의원 | `/^의원$/` | 의원 1,755 | ✓ |
| 보건기관 | `/보건/` | 보건진료소 949, 보건지소 643, 보건소 58, 보건의료원 14 | ✓ |

### 2-3. 자가용 판정 `judgeCar` (서버에 없음, 화면 전용)

```
마을 안에 그 종류 시설 있음(응급 제외) OR 가까운 시설까지 자가용 분 ≤ 기준  → 0
그 외(길 없음 포함)                                                        → 2
```
- 자가용 탭 기준 분은 화면 전용 값(`carView`)이고, 결과·레포트는 서버 기준 분으로 계산한다.

## 3. 의료·교통 취약도 (`src/api/vuln.ts`)

서버에 점수가 없어 서버 군 지표(`indicators`)로 화면에서 계산한다. **0점 = 가장 좋음, 50점 = 기준선, 100점 = 가장 나쁨.**

### 3-1. 지표 점수식

| 지표 | 원자료 | 점수식 | 50점 기준 |
|---|---|---|---|
| E30 응급실 30분 밖 | `indicators.e30` (전체 주민, 지역응급의료센터 이상) | `ratioScore(e30, 0.3)` | 30% |
| E60 권역센터 60분 밖 | `indicators.e60` | `ratioScore(e60, 0.3)` | 30% |
| 의사 수 | `doctorsPer1k` (없으면 `doctors/pop×1000`) | `1 − 의사/(2×0.9)` (0~1로 자름) | **0.9명(72개 군 평균, 코드 고정)** |
| 대중교통 최소서비스(MS) | `stopShare`, `runsShare` | `ratioScore(1−MS, 0.2)`, MS = 정밀 (공간+시간)/2, 간이 공간만 | 확보 80% |
| 정류장 걷는 시간 | `walkMin` | `walk/30` (0~1로 자름) | 15분(설정값) |

`ratioScore(v, std)` = v ≤ std이면 `0.5·v/std`, 아니면 `0.5 + 0.5·(v−std)/(1−std)` (두 구간 선형, 0~1)

### 3-2. 합산

```
의료 취약도 = 100 × (0.4·E30 + 0.3·E60 + 0.3·의사) / (자료 있는 가중치 합)
교통 취약도 = 100 × (0.57·(1−MS) + 0.43·걷는 시간) / (자료 있는 가중치 합)
응급의료 취약지 배지 = E30 ≥ 30% OR E60 ≥ 30%  (보건복지부 고시 정의와 같음)
```
- 교통 가중치는 원래 MS 0.4 · 교통사고 0.3 · 시간 0.3에서 사고(자료 없음)를 빼고 비율대로 나눈 값.
- 가중치는 코드 주석상 "팀 확정 전 예시값".

### 3-3. 게이지 상태 문구
- 50점 이상 위험, 30~50점 주의, 30점 미만 양호. "가장 나쁜 지표"는 지표 점수 최댓값.

## 4. 응급실 30분 밖 인구 (진단 화면 카드)

`villageTimes` + `overLimit` (`src/api/vuln.ts`)
```
마을 분 = nearest.er.center.minutes (지역응급의료센터 이상, 길 없으면 null)
공백 인구 = Σ 인구[분 > T 또는 null]   · 비율 = 공백/전체
평균 분 = Σ(분×인구)/Σ인구  (길 없는 마을은 평균에서 제외)
```
- 진단 카드는 **고른 나이대** 인구로 T=30분을 센다. 지표 E30(`indicators.e30`)은 **전체 주민** 기준이라 나이대가 다르면 숫자가 다르다(화면에 "지표 E30은 전체 주민 기준"으로 표기).

## 5. 지도 바탕 시간 격자 (`src/api/cells.ts` `erGrid`, `src/map/MapView.tsx`)

```
칸 크기 = 군 경계 긴 변 / 60   (약 600m 안팎, 위도에 따라 경도 간격 cos 보정)
칸 값(분) = 가까운 마을 6곳의 '고른 시설까지 자가용 분'을 거리² 역가중 평균 (각 값은 180분에서 자름)
  · 고른 시설 분: targetMinutes — 마을 안에 그 종류 시설이 있으면 0분, 응급은 er.center
칸 인원 = 칸 안에 좌표가 든 마을의 고른 나이대 인구 합
옅게 칠함 = 가장 가까운 마을이 1.2km 밖 OR 칸 인원 0명   (진하게: 불투명 150/255, 옅게: 45/255)
색 = 10분 진초록 → 20분 연두 → 30분 노랑 → 45분 이상 주황 (모든 군 같은 눈금)
```
- 칸 단위로 잰 값이 아니라 **마을 값을 퍼뜨린 그림**이다. 칸 인원은 마을 좌표가 칸 안에 있을 때만 잡혀서 마을 근처 칸도 0명이 될 수 있다.
- 결과 화면 격자는 진단에서 마지막으로 고른 시설 필터(`gridTarget`)와 나이대로 칠한다(계산 숫자에는 영향 없음).

## 10. 발견 사항

### 바로 손볼 만한 것

**(A) 첫차 추정값이 판정에 그대로 쓰인다**
- 실데이터: 정밀 지역 마을 중 **3,292곳**의 첫차가 TS-BIS 추정값(`bus.firstEstimated = true`)이다.
- `judgeLocal`은 추정 여부와 상관없이 `firstToTownMin < 720`으로 판정한다. 서버 판정도 같은 값을 쓰는 것으로 보이지만, 추정값으로 판정이 갈리는 마을이 몇 곳인지 화면에서는 알 수 없다(팝업에만 "(추정)" 표시).
- 제안: 서버와 함께 "추정 첫차로 판정이 바뀐 마을 수"를 지표로 보여 주거나, 판정 설명에 추정 여부를 남긴다.
- **답(2026-10-27):** 추정 첫차 3,292곳 중 그 값으로 판정이 갈리는 곳은 통과 2,735곳 · 탈락 94곳이다. 레포트 한계에 이미 적혀 있다. About의 판정 기준에도 추정값을 같은 규칙으로 판정한다고 적었다.

**(B) 의사 수 기준 0.9명이 코드에 고정돼 있다** (`STD.avgD`, 2026-10-24 계산값)
- 서버 데이터가 바뀌면 의료 취약도 점수가 기준과 어긋난다.
- 제안: 서버가 72개 군 평균을 `/api/health`나 지역 목록에 내려 주고 화면은 그 값을 쓴다.
- **답(2026-10-27):** 교도소 · 부속의원 등 주민이 쓸 수 없는 의원을 정리한 뒤에도 72개 군 평균은 0.899명이라 0.9를 그대로 둔다.

**(C) What-if 곡선이 안 순서에 기댄다** (`plans[length − 1]`)
- 서버가 안 순서를 바꾸면 곡선과 "가장 많이 닿는 안"이 다른 안을 가리킨다.
- 제안: 이름이나 서버의 명시 필드(예: "예산 안 최대 달성 안" 표시)로 고른다. 지금 응답에는 그런 필드가 없어 서버와 합의가 필요하다.
- **답(2026-10-27):** 서버 응답의 `k`(0 비용 절감 · 1 균형 · 2 적극 투자)가 명시 필드다. `WhatIf.tsx`는 순서 대신 `k === 2`로 고르도록 고쳤다.

### 알고 쓰면 되는 것(표기·설계 한계)

- 브라우저 판정 규칙은 서버 결과에서 역추정한 것이다. 서버와 다르면 서버 결과를 쓰고 "서버 판정과 N곳이 달라요"로 알린다.
- 진단 응급 카드(고른 나이대)와 지표 E30(전체 주민)은 기준 인구가 다르다(화면에 표기됨).
- 취약도 가중치·걷는 시간 15분은 팀 확정 전 예시값이다.
- 바탕 격자와 랜딩 칸은 실제 격자 측정이 아니라 마을 값을 퍼뜨린·묶은 그림이다(범례·FAQ에 표기됨).
- 순회 진료 노선은 정류장 사이 직선이다. 도로를 따라가려면 경로 탐색 자료가 필요하다.
- 결과 "새로 닿음"은 coverage 0.5 초과로 자른 개수다. 레포트 비교표의 서버 값(`reachedVillages`)과 기준이 다를 수 있다.
