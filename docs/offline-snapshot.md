# 백엔드 전체 장애 대응: 정적 스냅샷

백엔드가 완전히 내려가도 정적 자료로 진단과 예산 시뮬레이션을 이어 가기 위한 구조를 적는다. 추정 계산 규칙과 서버 비교는 [estimated-simulation.md](estimated-simulation.md)에 있다.

## 현재 상태

| 항목 | 상태 |
|---|---|
| 정적 자료 | **59개 지역.** `public/data/snapshot/`. 이용 조건과 ODbL 대응은 [data-licenses.md](data-licenses.md) |
| 나머지 13개 지역 | 서버가 정상일 때 기존대로 쓴다. 서버 전체 장애 때는 지원하지 않는 지역으로 안내한다 |
| 비공개 전체 수집본 | `snapshot.local/`(Git 제외). 72개 지역. 공개 파일은 여기서 만든다 |

## 1. 상황별 동작

| 상황 | 지역 자료 | 계산 | 화면 표시 |
|---|---|---|---|

## 2. 파일 구조

```
public/data/snapshot/
  manifest.json              처음에 받는 파일. 약 39KB
  LICENSES.txt               자료별 출처와 이용 조건
  48740.json ...             공공데이터 파일. 지역 하나당 하나
  osm/index.json             지역 중심과 카드 지표의 OSM 파생 칸(ODbL)
  osm/README.txt             ODbL 고지와 만든 방법
  osm/48740.json ...         OSM 파생 파일(ODbL). 지역 하나당 하나
```

**manifest.json**(schema 3): `schema` · `dataVersion` · `capturedAt`(수집일) · `origin` · `complete: false` · `totalRegions` · `totalVillages` · `tiers` · `regions`(중심 좌표 제외) · `unsupported`(13곳의 코드 · 이름 · 시도) · `defaultState` · `files`(공공데이터 파일과 `osm` 파일의 경로 · 크기 · gzip 크기 · SHA-256, 마을 수) · `osmIndex` · `sources`.

**지역 파일:** `{ data, map, notes }`. `notes`는 서버 레포트 각주의 출처, 기준 시점, 이용 조건이다. **OSM 파일:** ODbL 고지 칸과 `depot`, `facilityVillages`, `indicators`, `villages`. 앱은 두 파일을 `mergeRegion`(`src/api/snapshotSplit.ts`)으로 합쳐 서버 응답과 같은 모양을 만든다.

**저장하지 않는 칸**: 앱이 읽지 않는 칸은 뺀다(`scripts/snapshot-check.mjs`의 `stripRegion`). `nearest.school`, `nearest.library`, `myeons[].pharmacy`, `bus.dailyRunsBis`, `indicators.runsShareBis`. 나머지 값은 바꾸지 않는다.

**읽을 때 검사**(`src/api/snapshot.ts`): 두 파일과 `osm/index.json` 모두에 HTML 응답 거부(없는 파일에 SPA 첫 화면이 200으로 온다), JSON 파싱, SHA-256 대조(보안 컨텍스트)를 하고, 합친 뒤 지역 코드 · 이름 · 등급 · 마을 수 일치, 마을 칸 검사(`validRegionData`), 경계 형식. 하나라도 틀리면 그 파일을 쓰지 않고 오류를 보여 준다. 실패는 기억하지 않아 다음에 다시 받는다. 성공한 파일은 페이지 안에서 다시 받지 않는다.

## 3. 장애 감지와 전환

- **바로 실패하는 장애**(연결 실패 · 5xx · 잘못된 응답): 요청이 곧바로 실패하므로 각 요청이 정적 자료 · 추정으로 넘어간다. 기다림이 없다.
- **답 없이 멈춘 서버**: 지역 목록 · 자료 요청이 `GRACE_MS`(4초) 안에 답하지 않으면 정적 자료를 먼저 보여 주고, 판정 · 대안 · 지역 자료를 60초 동안 장애로 기억한다(`markHung`). 그동안 계산은 서버를 부르지 않고 바로 추정한다. 늦게라도 답이 오면 서버 값으로 바꾼다.
- 카드 72개가 지역 파일 72개를 받지 않도록, 지역 카드의 지표는 manifest에서 읽는다.

## 4. 복구

- **버튼**: '서버로 다시 계산' · '서버 다시 확인'은 `retryServer`를 부른다. 먼저 `/api/health`를 4초 안에 묻고, 연결이 안 되면 다른 API를 부르지 않고 값을 그대로 둔다.
- **자동**: 저장 자료나 추정을 쓰는 동안만 60초마다, 탭으로 돌아왔을 때, 네트워크가 다시 붙었을 때 `recheckServer`가 `/api/health`만 묻는다. 정상 상태에서는 아무것도 부르지 않는다.
- **전환**: 받기 전에 화면을 비우지 않는다(`refreshRegion`). 받은 자료가 저장본과 같으면 객체를 그대로 둬 지도와 입력이 움직이지 않고, 다르면 옛 자료로 만든 판정 · 대안을 버리고 새 자료로 다시 계산한다.
- **유지되는 것**: 지역 · 예산 · 목표 · 공급수단 · 단가 · 고른 안 · 바꿔 본 What-if 예산.
- 복구 요청은 `cache: 'no-store'`로 보내, 멈춘 요청이 쥔 HTTP 캐시 잠금과 캐시된 옛 응답을 피한다.

## 5. 데이터 이용 조건

자세한 내용은 [data-licenses.md](data-licenses.md)에 있다. 공개 판정표는 `scripts/snapshot-sources.json`이고, 공개 고지는 `public/data/snapshot/LICENSES.txt`와 `public/data/snapshot/osm/README.txt`다.

**민감정보 검사:** `scanSensitive`가 전 지역의 문자열 값과 칸 이름에서 키 · 토큰 · URL · 주민번호 · 전화번호 · 이메일 · 내부 IP · 서버 경로 형태를 찾는다. 72개 지역에서 발견 0건이다. 시설 이름 일부에 의원 이름으로 쓰인 사람 이름이 들어 있으나 공개 시설 정보다. 형태 검사이므로 민감정보가 없다는 증명은 아니다.

```bash

```

```bash

```


| 기능 | 원인 |
|---|---|

## 8. 로컬에서 완전 장애 재현

운영 서버를 건드리지 않고 재현한다. 앱을 빌드할 때 없는 주소를 넣으면 모든 API 요청이 연결 실패한다.

```bash
VITE_API_URL=http://localhost:9 npm run build
```

```bash
npx wrangler dev --port 8787
```

`http://localhost:8787`을 시크릿 창으로 연다. 500 · 무응답 같은 다른 장애는 작은 프록시를 앞에 두고 `VITE_API_URL`을 그 주소로 빌드하면 된다. 끝나면 `npm run build`로 `dist/`를 되돌린다.

## 10. 유지관리

- 서버 스키마가 바뀌면 `checkRegion`이 수집을 실패시킨다. 새 칸이 앱에 필요하면 `stripRegion`을 확인한다.
- 수집일이 오래되면 화면의 수집일로 드러난다. 이용 조건 표는 자료가 추가될 때 다시 확인한다.
- `scripts/snapshot-all.test.ts`는 스냅샷 폴더가 있을 때만 돈다.
- 출처 표시 의무(공공누리 제1유형 · CC BY · ODbL)는 공개 때 '가정과 출처' 시트와 추정 요약의 출처 목록으로 표시한다. 공개 전에 문구를 팀이 확인한다.
