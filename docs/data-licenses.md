# 정적 자료의 이용 조건과 ODbL 분리

서버 전체 장애 때 쓰는 공개 정적 자료(`public/data/snapshot/`)의 범위와 근거다. 공식 표시는 2026-11-07에 다시 읽었다. 이 문서는 법률 자문이 아니다. 구조와 전환은 [offline-snapshot.md](offline-snapshot.md)에 있다.

## 1. 공개 범위

| 구분 | 지역 수 | 내용 |
|---|---:|---|
| 정적 자료에 포함 | 59 | 원자료 표시를 확인했고 ODbL 파일과 맞지 않는 조건이 보이지 않은 지역 |
| 서버가 정상일 때만 지원 | 13 | 진도, 강화, 보은, 청양, 홍성, 금산, 예산, 예천, 태안, 양양, 장흥, 영동, 괴산 |

13곳은 군 시간표나 경로당 자료의 공식 표시가 서로 다르거나, 페이지에 이용 조건 표시가 없어 정적 자료에 넣지 않았다. 판정은 [scripts/snapshot-sources.json](../scripts/snapshot-sources.json)에 출처별로 있다. 표에 없는 출처나 보류(`hold`) 출처를 쓰는 지역은 `make-public-snapshot.mjs`가 넣지 않고, 보류 지역 목록이 달라지면 저장하지 않고 멈춘다.

## 2. 파일 구조와 라이선스

| 파일 | 조건 | 담는 값 |
|---|---|---|
| `manifest.json`, `<코드>.json` | 값마다 원자료 조건([LICENSES.txt](../public/data/snapshot/LICENSES.txt)) | 마을 id · 이름 · 읍면 · 인구 · `a80In10y`, 시설 이름 · 종류 · 좌표 · 의사 수, 읍면, 경계, 출처 |
| `osm/<코드>.json`, `osm/index.json` | **ODbL 1.0**([README.txt](../public/data/snapshot/osm/README.txt)) | 전체 마을 좌표, 경로당 유무, 버스 값, 가까운 시설 결과, 시설의 마을 연결, 지역 중심, 인구 · 고령 비율 외 지표 |

**나눈 기준:** OSM에 조금이라도 의존하는 값은 모두 ODbL 파일에 둔다. 비OSM 값이 ODbL 파일에 들어가는 것은 공유 범위가 넓어질 뿐이지만, 그 반대는 ODbL 공유 의무를 어길 수 있다.

**공공데이터 파일을 ODbL로 내지 않는 근거:** [공동 DB 지침](https://osmfoundation.org/wiki/Licence/Community_Guidelines/Collective_Database_Guideline_Guideline)은 한 자료 종류가 지역 안에서 전부 비OSM이면 독립된 자료로 본다. 인구, 시설 속성, 읍면 경계가 여기에 해당한다는 해석이다. 두 파일은 법정리 코드와 시설 id로만 잇는다.

## 3. 59곳 원자료와 ODbL의 충돌 확인

[ODbL 제4.4조 d](https://opendatacommons.org/licenses/odbl/1-0/)는 파생 DB에 이 라이선스의 권리와 맞지 않는 내용을 넣지 못하게 한다. ODbL은 상업 이용과 변경을 허용하므로, 상업 금지나 변경 금지 자료가 ODbL 파일에 들어가면 충돌한다.

| ODbL 파일에 들어가는 비OSM 값 | 원자료 | 공식 표시 | 판단 |
|---|---|---|---|
| 경로당 좌표 · 유무 | 표준데이터 제공기관 파일, 군 · 도 포털 파일, 경기데이터드림 | 제한 없음, 상업 · 변경 허용 | 표시상 충돌 없음 |
| 손으로 정한 대표점 | 학교 표준데이터, 전국 정류장 | 제한 없음 | 표시상 충돌 없음 |
| 버스 횟수 · 첫차, 정류장 | TS-BIS, TAGO, 전국 정류장, 담양 BIS, 창녕 · 영양 · 양평 시간표 | 제한 없음 | 표시상 충돌 없음 |
| 곡성 버스 값 | 곡성군 시간표 | 공공누리 제1유형 | 상업 · 변경 허용. 출처 표시를 파일에 유지 |
| 가까운 병의원 이름 · 종류 | 건강보험심사평가원 | 공공누리 제1유형 | 상업 · 변경 허용. 출처 표시를 파일에 유지 |
| 응급의료기관 이름 · 종류 | 국립중앙의료원 | 제한 없음 | 표시상 충돌 없음 |
| 지표의 인구 가중치 | 행정안전부 인구 | 제한 없음 | 표시상 충돌 없음 |

**확인된 사실:** 59곳이 쓰는 출처에 공공누리 제2 · 3 · 4유형과 표시 없는 자료는 없다(`scripts/public-snapshot.test.ts`가 지역마다 검사한다). 제2 · 4유형 표시가 있는 진도 · 강화 자료는 ODbL 파일에도 공공데이터 파일에도 없다.

**법률적 해석(확정 아님)**

- 제1유형의 출처 표시 조건은 ODbL의 권리를 줄이지 않는다고 본다. ODbL 제2.4조는 개별 내용물의 권리를 건드리지 않고, 제4.2조 c는 고지를 유지하게 한다. 그래서 파일마다 `contents`에 출처와 조건을 적었다.
- '이용허락범위 제한 없음'에는 재배포 허용 문구가 따로 없다. [공공데이터법 제3조](https://www.law.go.kr/법령/공공데이터의제공및이용활성화에관한법률/제3조)에 근거해 표시상 허용으로 분류했다. 경로당 표준데이터는 통합 페이지에 표시가 없어 제공기관별 파일의 표시를 따랐다.
- OSRM 분 값이 파생 DB인지 산출물인지는 공식 답이 없다. 파생 DB로 간주해 ODbL로 제공한다.
- 행정 경계 원자료의 공공누리 제1유형은 가공자의 라이선스 파일에 근거한다. SGIS 경계 목록에서 표시를 직접 읽지는 못했다.

## 4. ODbL 의무 대응

| 의무 | 대응 |
|---|---|
| 라이선스 사본 또는 주소를 파일과 문서에 포함(제4.2조) | ODbL 파일마다 `license` · `attribution` · `notice`, `osm/README.txt` |
| 동일 조건 공유(제4.4조) | OSM 의존 값을 모두 ODbL 파일로 분리 |
| 산출물 고지(제4.3조) | 지역 선택, 진단, 결과 범례, 레포트, 추정 요약, 가정과 출처, 프로젝트 정보에 OpenStreetMap과 ODbL 링크(`src/ui/OsmNotice.tsx`) |
| 기계 판독 사본 무료 제공(제4.6조) | `osm/*.json` 정적 제공, 화면의 '파생 자료 받기' 링크, 만든 방법은 `osm/README.txt` |
| 추가 제한 금지(제4.7조) | 로그인 · 사용 제한 없음. SHA-256은 앱의 무결성 검사에만 쓴다 |

**남는 판단:** 13곳의 OSM 파생값은 이번 정적 파일에 없다. 서버 정상 때 공개 API에서 제공되고 만든 방법은 `osm/README.txt`에 있지만, 이것이 제4.6조를 충족하는지는 법률 판단이 필요하다. 서버 API의 진도 · 강화 값에 OSM 추정값이 섞이는 문제도 운영 서버에 그대로 남아 있다.

## 5. 값 검증

| 검사 | 방법 |
|---|---|
| 서버와 대조 | `npm run snapshot:public:verify`: 59곳을 합쳐 서버 응답과 칸 순서까지 비교 |
| 비공개 전체본과 대조 | `scripts/public-snapshot.test.ts`: 합친 값, 판정, 대안, 민감도, 취약도, 마을 카드 |
| 공개 조건 | 보류 출처 없음, 공공데이터 파일에 OSM 칸 없음, 보류 지역 파일 없음, ODbL 고지 있음 |
| 앱 동작 | `src/store.offline.test.ts`, `src/screens/unsupported.screens.test.tsx` |

## 6. 만들기

```bash
npm run snapshot
```

```bash
npm run snapshot:public
```

```bash
npm run snapshot:public:verify
```

`snapshot:public`은 서버를 부르지 않고 비공개 수집본에서 값을 나눈다. Node 22.18 이상이 필요하다(스크립트가 TypeScript 파일을 바로 읽는다). 자료나 출처가 바뀌면 `scripts/snapshot-sources.json`의 판정을 먼저 다시 확인한다.
